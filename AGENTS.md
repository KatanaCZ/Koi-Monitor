# Working on Koi Monitor

Koi is a native Windows monitor with a calm, playful personality. Preserve its
behaviour and pond/sakura atmosphere. Read `CONTRIBUTING.md`,
`docs/marketing-context.md`, the README, changelog and relevant source before editing.
Check the branch and working tree first; preserve existing work and stage only
changes belonging to the task.

## Required release procedure: cleangithub

Whenever the user asks for a new version, a version bump, release preparation or
`cleangithub`, follow `docs/RELEASING.md` before creating the release commit.
This also applies when a version bump becomes necessary during another task.
Apply the procedure to the release diff, not as a reason to rewrite the repository.
Do not skip editorial review because automated checks pass.

For pull requests, read and use `.github/pull_request_template.md`. State checks
actually run and their results, including failures and checks that could not run.
Keep commits focused and use English Conventional Commit titles. Write useful code
comments in English; preserve licenses, attribution and provenance. Never rewrite
shared history or remove agent instructions merely to hide assistance.

Prepare and verify authorized work without asking about routine reversible choices.
Pushing, merging, tagging, publishing and deploying require authorization within the
current task. A request to prepare a version alone does not authorize publication.
